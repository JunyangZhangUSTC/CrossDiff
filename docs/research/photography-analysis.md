# 摄影对比：分析图表、局部取样与结论边界

调研日期：2026-10-02。本文记录实现前的摄影插件设计调研；当前已交付范围以[实现规格](../architecture/photography-comparison.md)为准。用户已确认：只做比较与动态选区，不做修图；同时支持不同作品和同源照片，优先比较自己的照片与参考作品的风格。本轮不确定计算参数、界面尺寸或完整开发排期。

本文用 **事实** 标记一手资料支持的内容，用 **推论** 标记分析得出的限制，用 **建议** 标记待确认的产品方案。以下名称仅用于标识技术来源，不用于产品宣传中的竞品比较。

## 1. 先让比较对象决定结论

**事实：** SSIM 原始论文研究的是参考图与失真图的图像质量关系，包含亮度、对比和结构比较；不是两个不同摄影作品的审美评价器。[论文与作者提供的资料](https://ece.uwaterloo.ca/~z70wang/publications/ssim.html)

**推论与建议：**

- **作品学习**作为默认入口：允许不同场景、尺寸和构图；比较明暗层次、色彩分布与指定局部。表达“右图暗部占比更高”“所选天空区域更偏青”，不解释为调整配方或质量排名。
- **同源检查**用于同一底片、不同导出、不同处理版本或确有空间对应的画面；先说明对齐、缩放和色彩转换，再使用像素差异等对应位置分析。
- 无对应场景不输出逐像素差异结论；两种模式都不提供“好坏分”“大师相似度”或审美总分。不同主题导致的分布变化，不应误判成调色差异。

## 2. 图表应回答什么

**事实：** 直方图按数值统计像素数量；波形保留画面水平方向与强度的关系；矢量示波图用角度与径向距离表现色相与饱和程度。它们表达的维度不同，不能相互替代。[Apple 示波器说明](https://support.apple.com/en-euro/guide/final-cut-pro-ipad/dev930ee989d/ipados)

**建议：** 首屏保留图片为主，分析区按“影调 / 色彩 / 细节 / 信息”组织；每个图表附一句可关闭的解释。专业内容渐进展开，不在首屏同时摆满仪表。

| 分析 | 给初学者的可读结果 | 给专业用户的展开内容 |
| --- | --- | --- |
| 影调 | 亮度分布、暗部/中间调/高光占比、明暗跨度 | RGB 分通道与叠加直方图、分位数、明确公式的局部对比统计 |
| 明暗位置 | 明暗分区覆盖图，点击高亮对应区域 | 亮度波形、RGB Parade；两图保持相同坐标刻度 |
| 色彩 | 主色群、饱和度分布、暗部与高光各偏什么颜色 | 矢量示波图、按色相分组的饱和度/明度分布、取样色值 |
| 端点 | 接近纯白/纯黑的面积与位置 | RGB 单通道/全通道端点统计、阈值、实际分析范围 |
| 细节 | 同倍率放大对照，观察纹理、锐化边缘、噪点 | 独立 ROI 与像素级取样；后续再验证噪声/边缘统计的适用条件 |
| 信息 | 尺寸、格式、相机、镜头、快门、光圈、ISO | 色彩配置、位深、解码方式、可用的拍摄与处理元数据 |

**建议：** 在直方图上悬停或选中一个范围时，照片中对应亮度/颜色的区域同步轻量高亮；反向框选照片时，图表即时显示所选区域的分布。这样初学者能把抽象曲线与天空、主体、阴影联系起来。高亮只是可关闭的分析叠层，不改变照片。

**建议：** 跨图片的分布图以有效像素占比归一化，两边共享坐标范围；否则大图片、较大的选区或独立纵轴会制造视觉差异。“对比度”显示已定义的统计量名称，而不是虚构一个可通用于所有照片的“对比度滑块值”。

## 3. 动态选区是分析操作

**建议：** 首版矩形选区即可，拖动与缩放时联动更新图表，结束拖动后补充精确统计。选区不裁切文件、不重采样源图、不改变保存内容；清除选区即可回到全图。

- **独立选区**默认用于作品学习：左侧框自己照片的天空，右侧框参考作品的天空；两边位置、尺寸和比例可以不同。
- **联动选区**用于同源检查：在已确认的对应关系下映射同一区域，不能把“相同屏幕坐标”当作“相同物体”。
- 取样点可选单像素或小范围平均，并注明实际取样尺寸。用户后续已确认首版保存多组分析区域；区域命名及跨会话保存细节待定，椭圆与多边形蒙版可后续增加。
- 每次结果显示“全图”或“选区”以及是否降采样。缩放看图不应悄悄改变统计范围；“只统计当前可见区域”如增加，必须独立显式开启。

这是产品方案，不是上述技术文档规定的交互。

## 4. 几个容易误导用户的边界

### 画面冷暖、拍摄色温、编辑色温不是一回事

**事实：** 官方白平衡文档区分相机提供的拍摄设置与基于画面计算的自动白平衡；对 RAW 与已渲染 JPEG/TIFF 的色温控制也采用不同含义。[Adobe 白平衡说明](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/image-tone-color.html)

**推论与建议：** 显示照片整体/分区的颜色倾向是可行的，但蓝天多不代表相机白平衡更冷。界面把“拍摄参数（文件记录）”“画面统计”“推测”分开；缺失快门或色温时写“未记录”，不反推精确数值。色温单位 K 只用于有明确来源或定义的值。

### HSL 明度不是物理亮度

**事实：** W3C 定义的 HSL 基于 sRGB；无彩色的色相没有实际区分能力，HSL 的 L 与感知明度模型并非同一量。[W3C HSL 与颜色模型](https://www.w3.org/TR/css-color-4/#the-hsl-notation)

**建议：** 色相统计把低饱和像素另列为“中性色”，避免灰色被归入红色。需要明暗测量时另用明确定义的亮度/明度指标，不把 HSL 的 L 标成亮度 Y。两侧使用相同颜色空间与规则，专业详情说明计量条件。

### 端点不等于拍摄时过曝或欠曝

**事实：** 渲染图的高光/阴影剪切可以通过像素端点观察，单通道端点与三通道同时到端点的含义不同。[Adobe 直方图与剪切说明](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/image-tone-color.html)

**推论与建议：** 命名为“当前解码图的高光/暗部端点”，避免直接声称传感器信息已丢失；夜景黑色背景与高调作品中的白色背景也不必然是拍摄错误。HDR、超范围浮点值和 RAW 的传感器饱和另有定义，不套用 SDR 端点阈值。

### 曲线不是从成片唯一可恢复的编辑历史

**推论：** 相同结果可以来自曝光、曲线、局部调整、渲染配置等不同组合。即使同一底片的两个版本有像素对应，也只能在假设下估计色调关系；两张不同作品更不能从直方图反推出原作者的曲线。建议首版展示分布或累计分布，不出现“还原大师曲线”“曝光应增加 0.7 档”等结论。若以后加入关系拟合，必须命名为“估计的映射”，呈现适用区域与拟合误差。

### 噪声、锐度和镜头问题需要局部语境

**事实：** 官方细节指南要求至少 100% 查看锐化；锐化涉及边缘对比，高频纹理、噪声与处理方式都会影响观感。镜头相关现象包括暗角、桶形/枕形畸变及色边。[Adobe 细节与镜头说明](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/retouch-photos.html)

**建议：** 首版优先可靠的 100% 同倍率双侧局部查看，提供参考网格观察透视/水平与边缘形状；不提供自动矫正或镜头修复。不同分辨率、重采样、纹理和处理管线未统一前，不把单一清晰度数字解释成镜头解析力，也不把纹理强度直接解释成噪声。

## 5. 计算基础与尚未确定项

**事实：** Core Image 支持输入→工作空间→输出的颜色管理，默认工作空间是线性 gamma 的扩展 sRGB。[Apple 工作色彩空间 API](https://developer.apple.com/documentation/coreimage/cicontextoption/workingcolorspace)

**建议：** 分开保存原文件描述、解码后的高精度分析数据、屏幕预览。分析不能读屏幕截图或沿用被压成 8 位预览的数据；应记录输入配置、解码版本、分析空间、有效像素范围与采样精度。无色彩配置文件时明确采用的假设。直方图、亮度值和色差必须使用同一比较契约，避免把显示转换产生的变化称为原图变化。

**后续确认：** 用户已选择默认双图、直方图和少量差异说明，专业图表按需展开；左右独立选区可联动，首版保存多组区域。影调分布与有记录时的处理曲线都纳入首版方向，专业指标必须采用 Apple 接口或成熟专业库。最新决策见[设计讨论](../architecture/photography-comparison.md)。是否导出报告、计算色彩空间、亮度定义、端点阈值、采样预算、HDR 呈现与 RAW 解码流程仍需形成技术规格。
