# Git 系统兼容性与 0.15.2 发布验证

## 问题与复现

0.15.0 的云端检查在第一次 HEAD → 暂存区比较时失败，未进入发布阶段。本地较新的 Apple Git 未暴露该问题。原实现依赖 `ls-files --format` 的 `objectsize` 字段，而较旧 Git 不提供该字段。

在项目内下载并编译官方 Git 2.39.5，没有安装到系统。最小 CLI 复现返回 `fatal: bad ls-files format: %(objectsize)`；将原 Git 核心检查使用的可执行文件换成这份 Git，保留原实现，其失败位置与 CI 一致。参考 [Git 2.39 的字段定义](https://git-scm.com/docs/git-ls-files/2.39.0)与 [cat-file 批量协议](https://git-scm.com/docs/git-cat-file/2.38.0)。

## 修复

- 使用稳定的 `ls-files --stage -z`，文件名仍按 NUL 分隔并保留原始 UTF-8 字节。
- 对暂存区实际引用的非子模块对象去重，每批最多 128 个完整对象 ID，通过 `cat-file --batch-check` 获取类型和字节数。避免每个文件启动进程，也不遍历整个对象数据库。
- 严格核对返回数量、顺序、对象 ID、类型和非负大小；缺失对象明确失败。保留索引变化检测，不写入源仓库。
- 有界 stdin 使用非阻塞读写，同时排空 stdout/stderr，保留超时、取消、输出限制与子进程提前关闭管道的保护。

## 随后发现的符号链接缓冲区问题

0.15.1 云端使用 Apple Git 2.39.5、Swift 6.1.2、macOS 15.7.9 arm64，通过暂存区与批量元数据检查后，在首次工作区符号链接读取时崩溃。本机 Swift 6.3.3 未复现。新增失败后的 LLDB 回放保留原退出状态，定位到 `GitWorkingAccess.read` 的 `Data(bytes.prefix(count))`；损坏地址包含链接目标 `mixed.txt` 的字节。

原因是旧 SDK 的 `readlinkat` 接收 `char *`，直接传入 `[UInt8]` 的 `&bytes` 会指向数组值而非元素存储。修复复用现有文件夹模块的 `withUnsafeMutableBytes` 模式，明确传入缓冲区地址及长度，不改变链接检查或跟随策略。新增短链接、中文及 emoji 链接、长链接的实际工作区扫描和预览字节回归。普通 `read` 的 `void *` 调用没有本次证据中的类型问题，未连带修改。

符号链接修复后的本机完整 Git 核心检查为 **137 项通过**，包含上述新增回归和大目录检查。

云端最终结论以主分支与正式 Release 工作流为准，失败构建不计通过。

本记录只证明上述实际测试的版本与范围，不宣称任意旧版 Git 或私有远程认证已全部验证。原始诊断与检查日志位于项目内忽略目录 `.build/git-compatibility/`。
