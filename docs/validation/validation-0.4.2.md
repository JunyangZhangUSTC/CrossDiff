# 0.4.2 图片四角缩放与翻转验收

日期：2026-10-01。环境：Apple silicon、macOS 26.6.2、Swift 6.3.3。产物：`dist/CrossDiff.app`，版本 `0.4.2`，构建号 `12`。

**当前状态：渲染几何、原生交互、完整窗口外观及应用构建检查通过。**

## 已完成的检查

- `bash scripts/tests/check-image-comparison.sh`：569 项断言通过。覆盖四角缩放、固定对角、锁定及解锁长宽比、独立宽高、旋转与水平／垂直翻转组合、尺寸边界、裁剪对齐、重叠区域、透明度、预览画布限制及取消。
- `bash scripts/tests/check-image-workflow.sh`：完整原生窗口交互检查通过。在检查进程内部派发原生鼠标事件，验证左右所有四角及 24 × 24 点命中区域、等比与非等比缩放、重锁保留当前比例、翻转和旋转后的角点拖动，以及固定对角不会变成整图平移。
- 角点拖动使用分段鼠标事件，在中间等待异步预览刷新后继续拖动并释放，验证中间渲染不会取消后续手势或遗留交互状态；左右操作独立，模式与标签切换保留参数，单侧重置恢复所有变换及比例锁。
- 数值字段支持 `140.05` 这样的百分比。未修改内容时仅聚焦再失焦，不会把四角拖动得到的精确变换量化为显示精度；旋转与翻转状态也得到保留。
- 比较前后读取源文件并逐字节核对，原图保持不变。测试使用项目内虚构图片、独立会话和偏好，不读取用户真实文件或使用系统剪贴板。
- 完整父窗口截图覆盖中英文、浅深色、1220／860 点宽度与四种比较模式。新增并排画布的像素检查，分别验证左右图片的蓝色、绿色和橙色测试内容可见，同时导出原始预览作对照；不能仅以控件存在或模型参数正确作为图片显示通过的依据。
- 本轮 `bash scripts/build-app.sh` Release 构建、`codesign --verify --deep --strict dist/CrossDiff.app` 及应用发布敏感信息规则扫描已通过。

原生交互日志、窗口截图和测试结果保存在 `.build-image-workflow-checks/renders/`；几何检查数据保存在 `.build-image-comparison-checks/`。这些生成物留在项目忽略目录，不提交 Git。

审阅截图时曾误判图片内容缺色。随后离线检查原截图与新一轮完整窗口截图，确认左右画布中的三种测试颜色数量一致，原始预览也完整；该判断不成立，没有据此修改产品配色或渲染逻辑。保留父窗口画布的颜色回归检查，临时诊断分支已移除并重新编译通过。

## 已定位并修复的手势问题

最初用三个角点组成的最小检查复现了拖动第一段后手势取消的问题：模型收到第一段位移，但后续拖动和鼠标释放没有正常完成。根因是开始交互时，条件裁剪切换了 SwiftUI 视图结构，使承载手势的视图身份发生变化。修复保留稳定的视图结构，仅调整裁剪行为；随后完整的分段鼠标拖动、跨中间渲染和释放检查通过。

## 验证边界

- 所有研发写入、缓存、测试数据和应用产物均在项目内。未验证 Intel、macOS 14 的实际运行、VoiceOver、真实输入法候选窗口或长期使用。
- 本轮未运行远端 CI，未发布新版本。当前仍使用手动对齐和最长边 1600 像素的预览；缩放、旋转与压缩可能引入重采样差异，不是全分辨率无损校验。
