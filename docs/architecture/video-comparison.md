# 视频对比：实现与后续设计

日期：2026-10-04。工作分支：`zhangjy/video`。**状态：0.14.0 源码开发预览，Video 0.1.0；未发布。M1 代码已接入，实际验收以文末记录和检查结果为准。**

用户已确认核心场景：同一素材的不同版本，包括剪辑、调色、压缩、加字幕；先交付原生双画面与手动对照，再逐步研发自动对应。界面延续 CrossDiff 的主题、控件与双语行为。

## 当前源码实现（M1）

从“新建… → 视频”选择两侧本地文件。默认双画面、双时间线与一套播放控制；打开后不自动播放声音，信息面板按需展开。

| 操作 | 当前行为 |
| --- | --- |
| 联动浏览与逐帧 | 默认同时间浏览，始终提示内容对应尚未确认；可切换基准侧，按实际样本呈现时间逐帧。缺少精确样本索引时明确降级，不用名义帧率假造逐帧。 |
| 手动时间对齐 | 解除联动分别找到画面，再“对齐当前帧”；也可输入偏移，约定 `tRight = tLeft + offset`。这是查看假设，不是整片内容匹配证据。 |
| 声音与循环 | 默认静音，明确选择左侧或右侧音轨；联动时可按基准侧在有效重叠范围内选段循环。 |
| 暂停画面对照 | 并排、滑动、差异共用当前帧对；滑动／差异时暂停取帧，播放回到并排浏览。显示各侧真实帧时间，不把旧帧当作新定位结果。 |
| 局部查看 | 暂停后独立框选区域，按需启用联动；最多保存 32 组命名区域，可恢复完整画面。区域、偏移和查看状态保存在本地会话，支持撤销／重做。 |
| 差异预览 | 两侧明确标记为 Rec.709 SDR，且解码画面或所选区域像素尺寸相同时，使用 Core Image 的色彩管理差异预览；不是全分辨率检测或编码质量分数。 |

**格式与资源：** 首版声明 MOV／MP4／M4V，由 AVFoundation 检查轨道、可播放性和实际解码能力，不能仅凭扩展名保证支持。单侧时长上限 24 小时；精确查看帧默认最长边 1600 像素，每侧缩略图最多 16 张、每张最长边 160 像素。不做整片像素预解码，不创建转码副本。

**色彩与内容边界：** HDR、色彩标记缺失或两侧尺寸不同仍可视觉查看，但不提供此版本的 SDR 差异图。首版没有自动片段识别、剪辑重排对齐、自动空间对齐、运动区域跟踪、实时播放差异、VMAF／PSNR／SSIM 或视频导出。两侧播放器的联动浏览不能替代暂停后核对真实帧时间。

**安装与隐私：** Base 与 Full 都有原生视频服务；Full 预装 Video，Base 可独立安装，不需要额外音频或摄影插件。Apple 框架由系统提供，不新增 FFmpeg 或模型依赖。视频、帧和音轨留在宿主，插件仅取得有界技术信息；本地文件与容器外部引用分别检查，禁止网络输入和外部媒体引用。

以下保留整体设计与 M2／M3 演进方向。涉及自动匹配、多段时间对应、专业图表或质量评估的内容均为后续设计，不能解释为 M1 已实现。

## 1. 产品定位：先回答三件事

1. **现在看到的是不是对应内容？** 左右各自来自哪个时间，是否只是同时间查看，还是手动确认／算法找到对应。
2. **这一处改了什么？** 用并排、滑动对照、局部放大和暂停帧差异，查看构图、颜色、字幕和压缩带来的变化。
3. **下一处值得看哪里？** 已确认的对应范围、分析发现的候选变化与用户保存的比较位置，支持定位和循环查看。

视频比较保持只读。时间偏移、ROI、预览缩放和手动配对只改变比较会话，不重新编码、写回或导出改动后的视频。首版不扩展成完整视频剪辑器。

播放器的“联动”与内容的“对应”分别表达。刚打开两片时可以按各自起点联动浏览，但界面应提示“同时间查看，内容对应未确认”，不能默认宣布它们已经对齐。

## 2. 推荐默认界面

推荐 **双画面工作台**。保留现有窗口、新建按钮、标签页和主题，不另造一套播放器窗口。

```text
┌ CrossDiff 原生标题栏：新建… / 会话 / 外观 ──────────────────┐
│ 视频对比   [并排 | 滑动 | 差异]       时间对齐…   局部   信息 │
│ 同时间查看 · 内容对应未确认                           本地只读 │
├───────────────────────────┬───────────────────────────────┤
│ A  原片名称        源时间   │ B  修改版名称         源时间   │
│                           │                               │
│         视频 A            │          视频 B               │
│                           │                               │
├───────────────────────────┴───────────────────────────────┤
│          上一帧  播放/暂停  下一帧     时间      声音 A/B/静音│
├───────────────────────────────────────────────────────────┤
│ A  源时间刻度 ─── 缩略图轨道 ─── 当前位置 ───────────────── │
│ B  源时间刻度 ─── 缩略图轨道 ─── 对应位置 ───────────────── │
│ 已选范围 / 轻量状态                         展开比较位置列表 │
└───────────────────────────────────────────────────────────┘
```

默认只显示画面、一组传输控制和紧凑双时间线。编码、码率、色彩信息、对齐参数与直方图放在可展开检查器内。专业参数逐步展开的方向与 Apple 的 [Layout 指南](https://developer.apple.com/design/human-interface-guidelines/layout)一致，具体布局是本项目的设计选择。

### 视觉约束

- 沿用 [`ComparisonTheme`](../../Sources/CrossDiff/ComparisonTheme.swift) 的冷白／灰蓝背景、低饱和蓝色强调、正文与分隔线；SF Symbols、系统字体与现有小号原生控件。时间使用等宽数字。
- 画面舞台使用左右一致的中性背景；浅色模式下工具栏仍然浅色。不用彩色渐变、模糊阴影或强装饰包围视频，以免影响对颜色的判断。
- 文件名保持简洁，中间截断；分辨率、编码等详细信息放入检查器。不要在画面上常驻两套巨大播放控件。
- 模式最多三个一级入口：并排、滑动、差异。透明叠加作为滑动比较的进一步选项，避免工具栏继续增长。
- 对应范围使用低饱和蓝色细带；变化用琥珀色提示并配文字／形状。只有确认的“仅左侧／仅右侧”采用与文本一致的删除／新增语义，未分析与未找到对应使用中性色。
- 面板开关不重建播放器。尊重减少动态效果、键盘与 VoiceOver；每个图标都提供中英文标签和说明。
- 默认参考现有 1220 点窗口；在最小 860 × 580 窗口中缩短时间线、压缩文件信息、按可用高度适应画面。检查器改为弹出层，辅助功能收进菜单，播放和逐帧保持可见。实际布局必须用原生窗口验证。

### 另外两个布局方向

| 方向 | 优势 | 作为默认的代价 |
| --- | --- | --- |
| A 双画面工作台（推荐） | 两侧来源清晰，适合先确定对应，再查看不同版本 | 画面宽度各占一半，需要全画面模式看细节 |
| B 沉浸式滑动对照 | 单一大画布，适合已对齐的调色和细节比较 | 尚未建立对应时容易误导；文件来源和独立定位不够直接 |
| C 比较位置审阅 | 左侧条目列表逐处定位，适合已经分析出的多段结果 | 初次打开没有结果，常驻列表挤占画面空间 |

建议以 A 为默认，让 B 成为画面模式，让 C 成为按需展开的比较位置列表，保持一个工作台内的信息层级。

本地可交互布局讨论稿位于 `.scratch/video-design/video-comparison-ui-prototype.html`，可直接手动打开。它有 A/B/C 布局、中英文、浅深色、示意时间线与参数面板；示意画面和数值不来自真实视频分析。原型不进入发行包，且不能直接作为 SwiftUI 实现。内置浏览器安全策略不允许本轮打开本地 `file://` 页面，因此尚未完成视觉验收，不能称布局已验证。最终窗口布局仍须通过原生验收。

## 3. 核心操作与状态

### 打开、播放与逐帧

“新建… → 视频 → 选择左右文件 → 开始比较”沿用现有入口。立即读取基本信息并加载首帧，时间线缩略图渐进出现。全片分析由用户显式触发，不阻塞第一眼查看，不自动播放声音。

一组控制操作两侧；可以解除联动，分别定位。声音明确选择 A、B 或静音，不同时播放两侧。播放开始前等待两侧就绪；任一侧卡顿，暂停并重同步，而不是让另一侧继续悄悄跑远。

空格键播放／暂停；左右方向键在视频画布获得焦点时逐帧，时间／数值输入框保留自己的键盘行为。菜单提供对应操作与快捷键。A/B 声音切换、区域循环、上一／下一比较位置放在可发现的控制或菜单里。避免占用现有全文搜索快捷键，也不全局拦截其他窗口输入。

逐帧默认以 A 的下一真实呈现帧为基准，用时间映射选取 B 覆盖对应时刻的帧；允许切换为 B 基准。不同帧率时，一侧前进而另一侧停留一帧可能是正确结果。不要用“左右各进一帧”假装内容同步。

### 手动时间对齐

最容易理解的动作是：**暂停 → 解除联动 → 分别找到相同画面 → 将当前两帧设为对应**。偏移数值放在“时间对齐…”内，约定方向为 `tB = tA + offset`；正值表示读取 B 中更晚的时间。

先支持固定偏移与命名的范围对；底层从第一天使用“多个对应范围”的模型，避免以后处理剪切时重做会话结构。多段配对的复杂编辑放到后续阶段。一对人工对应帧只建立固定偏移的查看假设，不能证明剩余全片都对应；跨剪辑点需要新锚点或独立范围确认。

时间映射、区域与空间调整可以撤销／重做，自动建议需显式应用，并保留恢复前的状态。选择范围只影响查看、循环和分析，不剪裁文件。

### 不同长度、缺帧与未对应区间

两侧时间线保留各自的源时间与长度。当前范围联动时保留真实时间标签，不能把右视频强行拉伸填满左视频的总时长。

超出一侧有效范围时显示“此侧无对应时间”；不能冻结最后一帧让用户误以为内容仍对应。进入内容对应模式后，当前落入映射空隙时暂停联动，并允许独立浏览或跳到下一已确认对应范围。同时间浏览模式仍可使用，持续显示“内容对应未确认”。插入、删除、重排需要片段级证据，不能从一次整体偏移自动得出结论。

### 局部画面比较

默认查看完整画面，同步缩放与平移只改变观察尺度。暂停时可以独立框选两侧 ROI，提供联动开关和多组命名范围。尺寸／构图差异下允许两侧 ROI 不同；统计只覆盖明确的有效区域。

图片智能对齐用于已配对帧的可选空间校准。默认保留原始构图；不会逐帧偷偷补偿缩放／防抖，使用户想看的改动被消掉。应用变换后显示覆盖范围，并允许恢复原始构图。

首版框选固定画面区域，不承诺运动主体自动跟踪。需要追踪的 ROI 后续再增加明确的时间锚点／跟踪模式。

## 4. 时间对应、空间对齐、画面差异分开实现

```mermaid
flowchart LR
    Input[本地视频 A / B] --> Probe[读取轨道、方向、色彩、真实时间]
    Probe --> Browse[立即原生浏览]
    Probe --> Candidate[用户触发：音频 / 视觉候选]
    Candidate --> Verify[多个时间点复核；保留歧义]
    Verify --> Pair[候选 / 已验证 / 人工对应范围]
    Browse --> Manual[当前两帧设为对应]
    Manual --> Pair
    Pair --> Frames[获取对应时间的真实帧对]
    Frames --> Spatial[可选空间校准与 ROI]
    Spatial --> Compare[并排 / 滑动 / 暂停差异 / 按需分析]
```

### 自动匹配（后续 M2／M3）

初步目标是固定速度同源素材，先验证固定偏移，再扩展局部片段。复用 Olaf 音轨指纹提出候选，但用视觉进行复核：同一背景音乐不证明画面相同。无音轨或换配乐时，后续采用独立视觉候选召回。

采用稀疏抽帧、有限候选、多个相邻时间点验证和候选区间精修，避免所有帧两两比较。已有 OpenCV SIFT／RANSAC 可以辅助视觉验证，但不能只靠一个画面就把整个区间标为已匹配。

结果保留重复、重排与不确定关系；不把“未找到”叫“已删除”。抽样结果显示分析覆盖范围，不能据此宣称所有帧完全一致。黑场、重复片头、静态镜头、相似场景不同 take 是必须拒识或保留歧义的样本。恒定变速、变速坡道、倒放、复杂转场后置。

方法、依赖与证据详见[对应关系研究](../research/video-matching-analysis.md)。

### 画面与质量分析

默认提供直观画面对照；暂停后才进入当前帧的精确检查。第一版不显示一个含义不明的“全片相似度百分比”。

- **滑动／差异图**：指出当前对应帧的变化，标明分析尺寸、区域与色彩口径，不自动解释成“压缩变差”或“修改了曝光”。
- **RGB／亮度分布**：可后续复用摄影的图表与成熟统计，默认收起。字幕也可能改变分布，不能把统计差值反推原作者调色参数。
- **PSNR／SSIM／VMAF**：后续作为压缩质量专题，不作为内容匹配器或审美打分器。显示参考侧、模型、颜色处理、采样范围和分析尺寸。当前已有 OpenCV core 的 PSNR；SSIM 所需 quality 模块、libvmaf 均尚未集成。[OpenCV PSNR](https://docs.opencv.org/4.12.0/d2/de8/group__core__array.html)、[OpenCV QualitySSIM](https://docs.opencv.org/4.12.0/d9/db5/classcv_1_1quality_1_1QualitySSIM.html)、[Netflix libvmaf](https://github.com/Netflix/vmaf)

## 5. 原生播放与精确检查的两条路径

建议先使用双 `AVPlayer` 和统一协调器获得流畅并排浏览。Apple 支持预加载后用共同 host time 锚定播放器时间，但它不保证两侧每次屏幕刷新都已经解码并显示了准确对应帧。[同步时间基](https://developer.apple.com/documentation/avfoundation/avplayer/setrate(_:time:athosttime:))

暂停／逐帧检查由独立取帧路径生成两侧帧，保留各自实际 PTS、来源版本和映射版本，成对发布。拖动过程允许快速近似缩略图，停止后再请求精确帧；只有后一种结果进入像素分析。零容差会增加等待，不能在等待时把上一帧的数值当成当前结果。[Apple 取帧容差](https://developer.apple.com/documentation/avfoundation/avassetimagegenerator/requestedtimetolerancebefore)

单 Metal 画布实时合成两路 `AVPlayerItemVideoOutput` 的方案留给技术验证：它能一起呈现已选定帧对，但仍需正确处理低帧率、缺帧和解码落后。若原型达标，再把滑动和差异视图扩展到播放中；首个版本可明确限定为暂停检查，不用明显漂移的热图充当实时比较。首版切到滑动／差异时暂停两侧并等待可靠帧对；点击播放时返回并排浏览，播放控件明确提示这一行为。

**所有内部定位使用有理时间和真实 PTS。** `nominalFrameRate` 仅是元数据，不能代替可变帧率、分数帧率、编辑列表或非零轨道起点。AVFoundation 类型与编译可用性见[Apple 原生研究](../research/video-native-playback.md)。

### 色彩和格式

AVFoundation、Core Image 和系统色彩管理负责解码与色彩转换，避免自写颜色矩阵。首版首先验证 SDR 成对暂停帧；HDR 原生播放与 HDR 数值测量分别声明支持状态。未经验证的 PQ／HLG／EDR 路径不输出假装专业的差异分数。

`AVAssetImageGenerator.dynamicRangePolicy` 需要 macOS 15，不能无条件用于本项目的 macOS 14 下限。14 上 HDR 精确帧路径需另验 VideoOutput／Reader 的线性浮点输出。缺失色彩标记时保留“不完整”状态，而不是静默套入 sRGB 后宣称准确。[Apple HDR 与 Metal](https://developer.apple.com/videos/play/wwdc2022/110565/)

首批格式验收目标是 MOV／MP4 中的 H.264、HEVC 和 MOV ProRes；这是测试目标，不是本轮已经验证的支持列表。按资产、轨道和真实首帧解码分别检测。首版不新增 FFmpeg，不按扩展名宣称任意 MKV／WebM／AVI 可用，也不要求用户安装 Python 或全局工具。

本地输入显式拒绝网络资源、直播和容器外部引用；设置 `AVURLAssetReferenceRestrictionsKey`，不能因 URL 是本地文件就假定容器不会请求外部媒体。[Apple 引用限制](https://developer.apple.com/documentation/avfoundation/avassetreferencerestrictions)

## 6. 模块与插件契约

现有原生专业视图由宿主白名单分派，JavaScript 不能直接新增任意 SwiftUI 界面。因此采用 **宿主视频能力＋官方 Video 插件**，并声明支持此领域的最低宿主版本。基础版／完整版均具备宿主能力，完整版预装插件，基础版通过现有安装流程启用。

M1 契约为 `videoAnalysis → videoTimeline → crossdiff.video/1`，只支持两方。视频、帧像素与 PCM 保留在宿主；脚本只接收有界源元数据，`options` 必须为空。结果严格限定为 `metadataDifferences` 与 `contentCompared: false`，由宿主重新核验差异；不传递路径、帧数据或对应关系。摘要明确“技术信息一致不代表画面相同”。详见[双语插件规范](../plugins/development.md#video-contract)。

宿主模块分工：

| 模块 | 接口负责的行为与约束 |
| --- | --- |
| `VideoComparison` / CrossDiffCore | 有理时间、源元数据与严格 schema 校验；不依赖 AppKit、SwiftUI 或 AVFoundation |
| `VideoWorkspaceState` / CrossDiffCore | 人工偏移、源位置、区域、循环和查看状态；不保存像素、正在播放状态或自动匹配声明 |
| `VideoSourceService` / 宿主 | 打开获准输入、返回能力与元数据、取真实时间帧；封装方向、缓存和取消 |
| `VideoPlaybackCoordinator` / 宿主 | 定位、联动播放、暂停、逐帧、声音选择；统一处理就绪、卡顿、时间映射和过期回调 |
| `VideoComparisonModel` / 宿主 | 成对暂停取帧、Core Image 差异预览、ROI、撤销与异步结果版本管理 |
| `VideoComparisonView` / `VideoCanvas` | 原生工作台与画布；视图不自行解码视频或推断对应关系 |
| 后续 `VideoCorrespondenceEngine` | M2／M3 研发方向，尚未实现；未来负责候选、覆盖、证据和歧义 |

领域数据至少区分 `sourceRevision`、源有效时间范围、轨道选择、方向／色彩元数据、`correspondenceID`、人工／音频／视觉证据、分析覆盖、实际左右 PTS 和预览设置。JSON 中的 64 位时间值使用无损十进制字符串配 timescale，拒绝非有限时间和越界范围；显示秒数不作为持久化唯一真值。

可直接借用音频 helper 的固定速度匹配输入思想、取消与版本管理模式，以及图片的暂停空间对齐。音频目前的 `AVAudioFile` 读取不能直接代替视频容器音轨提取；图片 CPU 静态 renderer 不宜每秒调用几十次充当实时视频画布；摄影当前 sRGB SDR 统计不自动升级为 HDR 视频分析。

具体接入入口：

- `Sources/CrossDiffCore/PluginProtocol.swift`、`PluginPackage.swift`：增加领域与配对白名单、输入／结果校验。
- `Sources/CrossDiff/PluginComparisonView.swift`：新增原生视频视图分派。
- `Workspace.swift`、`CrossDiffCore/TextFileIO.swift`：标签内模型、关闭清理、向后兼容的可选视频状态。
- `NewComparisonModel.swift`、`NativeMenuController.swift`：视频输入入口和播放命令；比较类型菜单继续按启用插件生成。
- `Workspace.swift` 文件路由：视频插件未安装／停用时给出准确入口，不把常见视频静默当作 Hex 文件打开。
- `Plugins/Official/Video/`、`scripts/plugin_inventory.py`：插件包、Full 清单、官方安装目录与宿主兼容版本；用户不需要另外安装音频或摄影插件来解锁宿主内部复用。

共享协议、Workspace、菜单、inventory 和构建入口也是其他分支可能修改的区域。实现交付需列明这些文件；通过 Git 合并协调，不复制其他工作目录覆盖。

## 7. 性能、生命周期与恢复

- 浏览优先：读到首帧即可展示，缩略图渐进生成；播放时降低后台分析优先级。视频不整片解码进内存。
- 拖动只保留最新定位请求，等待稳定后生成精确帧；缓存按源版本、轨道、时间、方向、色彩口径与分析版本区分。
- 明确限制缩略图缓存字节、同时解码数、分析抽样数、临时 PCM 和磁盘预算。具体默认值由技术原型实测后确定；不能把系统解码器的全部内存占用说成自己已硬限制。
- 原文件变化、输入更换、关闭标签、停用／卸载插件时停止两侧播放，取消 reader／取帧／匹配，注销 observer，拒绝旧任务发布；清理仅限本任务创建的私有缓存。
- 轻量会话保存文件引用、人工对应、区域和查看方式；恢复时重新核对源版本。恢复不自动播放，不把旧自动候选当成仍然有效的事实。
- 缓存可能包含可还原画面和音轨，同样属于用户内容。继承项目本地、无遥测、可清除的约束，不增加云端分析。

## 8. 研发顺序与验收门槛

| 阶段 | 交付 | 进入下一阶段前的验证 |
| --- | --- | --- |
| M0 原生技术样机 | 用合成视频验证双路播放、PTS 定位、不同帧率、暂停帧对和色彩切换；比较双图层与单画布成本 | 测真实输出时间和帧编号，不只检查状态变量；列清可用格式、延迟、内存与降级行为 |
| M1 完整可用插件 | 安装／卸载、新建双文件、流畅并排、统一控制、基准侧逐帧、手动时间对应、选段循环、暂停滑动／SDR 差异、局部查看、中英文浅深色 | 核心交互可靠，当前比较来源清楚，最小窗口可用；源文件不变、取消无旧结果、恢复不串音 |
| M2 辅助自动对应 | 先验证固定偏移，再扩展固定速度局部片段；音轨候选与视觉复核、确认／撤销、重复与重排 | 测错误对应、召回、边界误差和覆盖；同 BGM 异画面／黑场／重复镜头不强行确认 |
| M3 专业增强 | 独立视觉召回、恒定变速、实时单画布对照、帧／片段专业图表、可选质量评估 | 有真实基准、明确口径和依赖分发方案后逐项开放 |

这是技术先后顺序，不要求每阶段单独公开发版。若用户要求首个公开版本包含自动对齐，可将通过 M2 门槛的固定偏移能力与 M1 一并交付；剪辑重排仍按局部关系单独验收，不能用一个偏移量代替。

最少测试集：相同文件、转码、加片头、单段删除、片段重排／重复、字幕、水印、调色、裁剪、不同帧率／VFR、竖屏方向、无音轨、音轨不同起点、同配乐不同画面、损坏／不支持／外部引用素材，以及快速 seek、换输入、关标签、插件卸载、会话恢复。素材在本项目内生成并保留真值时间映射。

视觉验收覆盖中文／英文、浅色／深色和 860 × 580／默认窗口，检查实际父窗口中的文字、画面、控制条与时间线。专业数值以可信库和已验证色彩管线为前提，不自写替代算法后标成专业结论。
