# CrossDiff · 对比一切

把对比这件小事做到极致。

状态：2026-10-02 产品方向。本文描述未来框架与能力规划，**不是当前版本的功能清单**；已交付功能见 [README](../README.md)。架构提案见 [框架设计](architecture/compare-everything.md)，插件接口草案见 [插件开发规范](plugins/development.md)。

0.5.0 建立插件框架后，已逐步实现 PDF、压缩包、摄影、API 与音频插件。当前 0.11.0 源码 Full 包含这些官方插件；具体发布状态、能力与边界见 [README](../README.md) 和 [实验插件规范](plugins/development.md)。本文中的整体目标仍按阶段推进。

## 产品定位

CrossDiff 是以原生 macOS 体验为起点、可通过插件扩展的比较工作台。帮助用户发现变化、理解变化，并在适用时安全地整理或合并变化。比较对象可以是文件，也可以是目录、页面、请求响应、记录、时间线或张量。

“对比一切”意味着能够不断增加新的比较对象和方法；不会宣称任意两种不相关的数据天然具有可解释的比较结果。比较之前必须说明对象、对应关系、比较规则与结果精度。

## 已确认的方向

- 原生 Mac 优先，美观、优雅和流畅是验收要求。基础操作简单，专业能力按需呈现。
- 免费开源，无账号或订阅门槛；主项目保持 AGPL-3.0-only。
- 先打通框架和一个真实插件，再补齐基础能力与更多领域插件，不一次重写全部现有功能。
- 基础能力也可采用官方内置插件交付，与外部插件共享能力注册和管理机制；0.7.0 的压缩包比较先验证这一方式，已有编辑器逐步适配。
- 同时设计双向比较、基于共同原始版本的三方合并，以及任意三个或更多对象的比较。先把文本三方合并做好。
- **首个官方插件为 PDF**：页面对照与可提取文字的差异；扫描件和 OCR 是单独的能力，不能把提取不到文字当作内容相同。
- 远程来源第一阶段只读比较，允许将整理结果保存到本地；远程写回单独实施。
- **首版插件框架就允许第三方本地插件安装**。默认使用无文件／网络接口的受限 JavaScript，保留逐版本明确批准的原生完全信任模式；两者已有实验实现，受限运行时不宣称操作系统沙箱。
- 摄影插件以只读分析和学习为核心，允许动态选取图片区域进行比较，不提供修图或调色功能；拍摄参数读取元数据，有记录时展示处理曲线，不从成片反推确定的快门、曝光或调色设置。
- 音频同时面向音乐与语音，优先比较同一录音的不同剪辑版本。分析、自动对应证据与手动试听分开：试听可独立调整速度／音高，当前自动对应只针对固定速度的同源片段，不等于已实现自动变速／变调识别。

## 本地优先与联网边界

当前本地比较离线完成，联网仅用于用户主动触发的 HTTPS 插件下载；API 导入不会发送请求或执行 cURL。远程来源仍在后续阶段，未来连接功能继续遵循以下原则：

- 本地比较可离线完成，不要求注册，不把内容发送到 CrossDiff 云服务。
- 宿主只在用户明确发起下载或未来的远程连接时联网，并说明目的地与用途；当前受限 JavaScript 不提供网络接口。
- 插件下载是代码分发行为，不应上传正在比较的文件。
- 远程服务会收到执行比较所需的读取请求；第三方插件的实际访问能力必须明确，不能把“独立进程”或权限声明误称为已实现的安全沙箱。
- 宿主管理的凭据不写入插件配置明文、分享报告、普通日志或可提交测试样例。缓存、历史记录、报告的保存范围和清除方式应可见。

完全信任模式运行的第三方原生代码可能拥有较广的文件与网络访问权限；宿主的联网和源文件保护策略无法作为对这类代码的强制保证。该模式必须明确标识，不能与受限插件共用“只访问授权输入”的安全说明。

受限 JavaScript 与显式完全信任模式已在 0.5.0 实验实现；来源能力授权与凭据代理仍为后续目标。

## 基础版的目标范围

| 能力 | 目标体验 | 需要明确的边界 |
| --- | --- | --- |
| 临时文本 | 直接粘贴、精细差异、搜索替换、编辑与合并 | 保留编码、换行、Unicode 和独立撤销 |
| 文本文件 | txt、Markdown、HTML、JSON、XML、YAML 等 | 原文比较是通用基础；结构比较与渲染比较必须明确选择规则，不静默规范化原文 |
| 文件夹 | 本地、SSH / SFTP、WebDAV、SMB、FTP 等来源自由配对 | 可比的是内容，不是要求两端协议相同；连接能力、读取完整性与错误必须显示 |
| 压缩包 | 作为虚拟目录，与压缩包或本地文件夹交叉比较，识别不同路径下的相同内容 | 不解压到磁盘；格式、加密、链接、完整性、读取预算与只读边界明确显示 |
| 图片 | 并排、叠加、分界、像素差异、对齐和变换 | 基础预览与摄影级高精度分析分开，明确分辨率与重采样 |
| 二进制文件 | 十六进制与字符视图、偏移、变化跳转、插入删除对齐 | 插入一个字节不能默认导致余下所有字节都被误报为修改；大文件要渐进处理 |
| 比较方式 | 双向、文本三方合并、多对象比较 | 各比较器声明支持的方式；“可以查看”不等于“可以自动合并” |

这些能力属于基础版的完整目标，不要求在框架第一个里程碑一次交付所有远程协议。具体顺序见 [路线图](roadmap.md)。

## 官方插件版图

| 插件方向 | 核心价值 | 专业视图与边界 |
| --- | --- | --- |
| 文档 / Office | Word、Excel、PDF、PowerPoint 的内容和版面比较 | 页面、段落、表格、单元格、幻灯片；公式与计算值、提取文字与页面外观分别处理 |
| API / 运维诊断 | HTTP 请求／响应的结构差异；网络包等另行扩展 | 当前导入 HTTP／cURL／HAR，比较状态、头、参数和 JSON 字段，忽略规则可追溯；不执行请求。普通日志复用文本比较，抓包与协议重组尚未实现 |
| 数据库 | 模式、表、记录与查询结果对比 | 明确行匹配键、类型、排序、空值及快照一致性；生成变更方案与执行变更分开 |
| 摄影 | 深入观察作品的色彩与影调差异 | RGB / 亮度直方图、HSL、对比度、亮度、色相、白场、黑场、高光、阴影与局部取样；快门、曝光与白平衡等显示元数据来源，不反推调色曲线或参数 |
| 摄影区域与成像分析 | 研究局部画面、构图及成像条件的差异 | 动态选区只改变分析范围，不修改照片；镜头、透视等分析的具体范围仍待设计，不提供校正编辑；RAW 支持明确到解码器和相机型号 |
| 音频 | 观察波形与频谱，定位同源片段及剪辑关系 | 当前支持 STFT、命名区域、手动 A/B 试听和固定速度片段候选；自动变速／变调、精确剪辑点及复杂混音仍待验证，未匹配不能当作确定删除 |
| 视频 | 定位画面、剪辑与音画变化 | 帧、时间线、同步播放、区域与颜色指标；可变帧率、色彩空间和编码噪声独立处理 |
| 模型 | ONNX / PyTorch 等结构、权重与张量分析 | 图、节点、参数表、形状、数据类型、误差分布与切片；不为读取差异默认执行模型代码，不把权重相近视为行为等价 |

插件方向是能力分组，并不要求每一组被打成一个巨大安装包。例如文档可拆为 PDF、电子表格、文字文档和幻灯片插件，摄影可按解码和分析能力组合。插件间复用必须通过明确契约，而不是互相读取内部状态。

## 发行组合

基础版与完整版已经使用**同一个应用、同一套插件机制、不同预装清单**。当前 0.11.0 源码基础版内置压缩包，完整版另含 PDF、摄影、API 与音频；其余专业组合仍是目标，避免维护多个功能分叉。

| 发行组合 | 预装目标 |
| --- | --- |
| 基础版 | 核心框架与基础比较能力 |
| 完整版 | 该版本、系统与架构下兼容的全部官方插件 |
| 摄影师版 | 基础能力与摄影、RAW 分析相关插件 |
| 媒体工作者版 | 基础能力与摄影、音频、视频相关插件 |
| 开发者版 | 基础能力与 API、数据库、模型等相关插件；普通日志使用文本比较 |
| 独立插件 | 可单独下载、安装、升级和卸载的扩展包 |

不同组合不形成付费等级。用户从基础版安装相同插件，应获得相同能力。当前官方目录可离线查看；用户主动点击“下载并安装”后，下载经校验的受限插件并启用，比较仍按需在本机运行。此入口只安装尚未安装的官方插件，已有外部插件更新通过本地包或任意 HTTPS 链接的审查流程完成；内置插件随应用升级。不会后台轮询或自动更新，也不会上传比较文件。未来专业组合的具体预装清单在相应插件实际交付后确定。

## 安装体验目标

三个入口复用相同的包校验与安装存储：应用内插件页、从 Release 下载后选择安装、拖入插件文件。官方目录将应用内固定的身份、版本、整包校验和与受限运行要求作为依据，用户主动点击后直接验证并安装；本地包与任意 HTTPS 链接则先展示名称、来源、能力和权限，经过用户审查后安装。损坏或不支持的包给出可操作原因。

管理界面已支持启用、停用、查看来源与版本，以及外部插件的上一版本回退和卸载；检查更新为后续目标。官方安装不会为原生代码授予完全信任权限，任意来源的原生插件均需单独授权。所有外部插件安装到独立数据目录，不要求用户复制文件进应用包。

## 美观与一致性原则

- 主窗口保留内容空间、原生菜单、轻量工具栏和稳定的比较标签。打开对象与安装插件应有清晰不同的反馈。
- 两侧以上时使用角色标签、布局切换、折叠基准或结果区，窄窗口不硬塞四个狭窄编辑器。
- 统一字体、间距、主题、快捷键、焦点、加载、错误与空状态；专业插件保留适合领域的页面、图表、波形、图结构等视图。
- “相同”需要完整证据；读取失败、部分扫描、取消、不支持、近似比较和未比较，均不能显示为相同。
- 每项指标都应能回答：比较了什么、依据什么规则、忽略了什么、精度是多少、如何定位回原始对象。
- 不把插件技术、运行时、协议或算法名堆到日常主界面；需要诊断时再展开详细信息。
